September 2026

What the job market is asking for

Twelve findings, each with what it means for this site. Primary sources — GitHub, Stack Overflow, State of JS, Naukri, the frameworks' own release notes — carry the weight. Figures from vendor blogs and job-board write-ups are marked directional: useful for which way things are moving, not for the exact number.

TypeScript is the default, not the upgrade

Primary

TypeScript became the most-used language on GitHub by monthly contributors in August 2025, passing Python and JavaScript — 2.6 million contributors, up 66% in a year. Frontend hiring guides report candidates without TypeScript being screened out earlier than a year ago.

TypeScript is the single largest gap on the shelf. Every JavaScript, React and Node chapter already assumes it exists; the topic behind that assumption is an outline.

GitHub Octoverse 2025 · Front End Interview Handbook

React is settled; Next.js is where the questions are

Primary

React is used by 83.6% of State of JS 2025 respondents, and the "framework wars" are described as over. Next.js is used by 59% of the same respondents and leads meta-frameworks while losing satisfaction. Next.js 16 made caching opt-in with use cache and Cache Components; React Compiler 1.0 shipped in October 2025 and is on by default in new Next.js and Vite apps; Server Component security advisories landed in December 2025.

Next.js is P0. React needs three sections it does not have: the Compiler, the RSC security advisories, and Actions in depth. Anything written about Next.js caching before 16 is now wrong by default.

State of JS 2025 · Next.js 16 · InfoQ

Node and Postgres are the backend half of nearly every JD

Primary

Node.js is the most-used web technology in the 2025 Stack Overflow survey at 49.1%, ahead of React. PostgreSQL has been the most admired and most wanted database three years running. Redis appears wherever caching, rate limits or queues do. On the ORM layer, Prisma and Drizzle are the two names in 2026 job-adjacent writing.

Node.js is P0 and SQL & Databases is P1, written Postgres-first with Drizzle or Prisma rather than a generic "databases" survey. Redis shrinks to the parts a product engineer uses.

Stack Overflow 2025 · Technology · Drizzle vs Prisma (directional)

AI engineering is now a web-developer skill

Primary + directional

In India, Naukri recorded AI/ML hiring up 33% year on year in July 2026 while overall IT hiring stayed modest. 84% of developers use or plan to use AI tools, 51% of professionals daily. Every major agent framework now ships a first-class TypeScript path — the Vercel AI SDK, Mastra (1.0 in January 2026), LangGraph.js — and MCP has become the interoperability standard.

This is the one topic that is not on the shelf at all, and it is the fastest-growing line in the Indian data. A new topic — AI engineering for JavaScript developers — is P0: calling an LLM, streaming UI, tool calling, structured output, RAG, evals, MCP, cost and safety.

Naukri JobSpeak July 2026 · Stack Overflow 2025 · AI · TypeScript agent frameworks (directional)

Interviews now include an AI round — and a code-reading one

Directional, consistent

Meta replaced one of two onsite coding rounds with an AI-enabled one from October 2025: sixty minutes in a multi-file codebase, fixing a bug, implementing, then optimising, with a model in a side panel. Google is piloting a code-comprehension round — read, debug and optimise existing code with Gemini available — and grades "AI fluency": prompting, validating output, debugging it.

The interview book has no round for either. Add AI-assisted coding and code comprehension as rounds, and a practice format built on reading and fixing an existing multi-file project rather than writing from blank.

Hello Interview · Meta · Exponent · Google

DSA still gates FAANG, but it is not the whole loop

Directional

A review of 74 recent loops found at least two dedicated coding rounds at every FAANG company, while Stripe, OpenAI and Anthropic leaned towards multi-part implementation and debugging. India's product companies keep the machine-coding round — Flipkart's frontend version is a two-hour build in plain HTML, CSS and JavaScript.

The DSA track's 245 exercises stay worth it. What is missing is practice for the other formats: a machine-coding exercise type (build a small UI to a spec, graded on structure) and multi-part implementation problems.

LeetCode discuss · 74 loops · Flipkart frontend SDE2

Frontend system design is its own round now

Directional, consistent

The 2026 frontend loop is described the same way across guides: recruiter screen, technical screen, coding, a frontend system design round, behavioural. The prompts repeat — news feed with infinite scroll, autocomplete, chat, a collaborative editor, an email client. Separately, AI-product design prompts — design a chatbot, a RAG document assistant, a coding agent — have become standard for AI-adjacent roles.

System Design is 61k words of backend design and has no frontend track and no GenAI track. Add both: roughly eight frontend walkthroughs and four GenAI ones, plus an exercise format of a prompt and a rubric.

Front End Interview Handbook · GenAI system design guide

Docker is expected; Kubernetes mostly is not

Primary + directional

Docker usage jumped 17 points to 71% in the 2025 Stack Overflow survey, the largest move of any tool. Job-market writing for JavaScript roles places Docker and CI/CD under required skills at the senior band, and treats Kubernetes as needed only where the job says so — most full-stack work ships to managed platforms.

Docker with CI/CD (GitHub Actions) is P1. Kubernetes drops to P3 and should shrink from 24 planned chapters to the eight a product engineer needs to read a manifest and talk to a platform team.

Stack Overflow 2025 press release · Docker for JS developers (directional)

Playwright won end-to-end testing

Directional

Playwright is described as the default recommendation for new projects in 2026, with roughly half of surveyed QA professionals on it against Cypress at around 14%, and several times Cypress's weekly downloads.

Testing is P1 and should be written Playwright-first for end-to-end and Vitest for units. This site already runs both in CI, which makes it the worked example.

BugBug · Tech Insider

OWASP rewrote its Top 10, and accessibility became law

Primary

The OWASP Top 10:2025 adds Software Supply Chain Failures and Mishandling of Exceptional Conditions, moves Security Misconfiguration to second, and folds SSRF into Broken Access Control. The European Accessibility Act has been enforceable since 28 June 2025 against WCAG 2.1 AA, and senior frontend interviews ask for an accessible combobox and the difference between the ARIA labelling attributes.

Web Security should be structured on the 2025 list, not the 2021 one. HTML is worth writing mainly for its accessibility half — move that up to P2, and make accessibility a required section in every frontend system design walkthrough.

GitLab · OWASP 2025 · Chromatic · EAA

GraphQL plateaued; tRPC and REST cover most TypeScript teams

Directional

GraphQL is reported settled at around a quarter of enterprise applications after its 2021–22 peak, with REST still near-universal and tRPC showing up in TypeScript-and-Next.js listings.

Do not write 22 GraphQL chapters. Fold it into one API-design unit — REST, GraphQL, tRPC, when each wins — of about six chapters, and move the rest of the budget to Node.

Pockit · API layers 2026

Juniors are hired on judgement, not boilerplate

Split signal

US write-ups put entry-level developer hiring down by around two-thirds since 2022, the tasks it used to consist of now done by AI. India's data points the other way: Naukri recorded fresher (0–3 years) hiring up 15–17% year on year through 2026. Both sides agree on what is screened for — reading unfamiliar code, reviewing AI output, debugging.

The audience this site is built for — Indian candidates — is in the better half of that split. The practice should match the screen: debugging and code-review exercises, not only write-from-scratch ones.

React: three new gaps from the market, six old ones

Depth

New since the last pass: the React Compiler (1.0, default in new apps), the Server Components security advisories of December 2025, and Actions in depth. Still open from before: streaming SSR, file upload, micro-frontends and React Native each deserve a section; i18n, state machines and feature flags are named but not taught. And 27 of 51 chapters still open into no exercise.

System Design: no frontend track, no GenAI track, no practice

Largest in-topic gap

The market now runs a frontend system design round and, for AI-adjacent roles, a GenAI one. This topic has neither, no cheat page, and zero exercises across 61k words. The exercise format is a prompt and a rubric, not a test runner — a content decision before it is a code one.

Interview book: rounds the site cannot teach, and rounds it does not have

Two problems

TypeScript, Next.js, Node/Nest, Databases/Redis and AWS/Docker/CI-CD each have a round and no written topic behind them — the P0 and P1 list above closes most of that. Separately, the book has no round for the AI-assisted coding or code-comprehension formats Meta and Google now run, and no frontend system design round.

Three things only some topics have

The pattern

Runnable exercises exist in JavaScript, DSA and React. Cheat pages exist for JavaScript, Git and React — DSA and System Design, two of the three largest topics, still have none. Guided projects exist in JavaScript and React. Git's shape — model, internals, commands, workflow, danger zone, interview bank, cheat sheet — is still the template worth writing down once and applying to every new topic from the start.

Practice formats the market now tests

New format

Every exercise on the site is "write a function from blank until the tests pass". The loops above also test machine coding (build a small UI to a spec), code comprehension (read and fix an existing multi-file project), and design (a prompt answered against a rubric). The sandbox already runs multi-file code; the missing piece is the exercise shape.

Deploy size is now a limit, not a preference

Hit the ceiling

The Hobby plan's deployment storage reached 11.21 GB of 10 GB. A weekly cleanup now keeps the count at about fifteen deployments, which fixes the total. It does not fix the size of each one: every deploy still copies 18 MB of wasm — Pyodide, sql.js, TypeScript's lib files — that loads only when a reader picks Python or SQL in the playground. Serving Pyodide from its CDN removes most of it.

Three pages still render nothing for a crawler

Measured again

On the current build /git emits 42 characters of visible text, /review 38 and /progress 23. The Git guide is still invisible to search engines. /problems, by contrast, emits over 20,000. The fix is the shape /architecture uses: server-render the body, keep only the interactive shell on the client.

Progress that survives the browser

Biggest product gap

Chapters read, exercises solved, streaks and review schedule all live in localStorage on one device. The storage layer is one seam — every progress-aware component reads through useSyncExternalStore, so a synced implementation touches no components.

Errors nobody sees

Seam exists

Client errors still post to /api/client-error and land in the function log: no grouping, no alerting, and the log expires. ErrorReporter.tsx is the swap point; no error service is installed yet.

A schema over chapters

Grows with content

Chapter bodies are HTML strings with no schema, so a malformed chapter renders oddly instead of failing the build. With 115 P0 chapters to write, a Zod check over the chapter shape pays for itself on the first mistake it catches.

Offline reading

Decision first

app/manifest.ts exists; the service worker does not. The App Router serves RSC payloads as well as HTML, so caching has to cover both — and the playground's wasm should never be precached by default.

The interview book as a product

Blocked

27 rounds and 230 questions, with three market-driven rounds to add, is still the most obvious thing here to charge for. It needs accounts, then payments, then a gate — and nothing in it starts before accounts do.

Smaller: the rate-limit action and a light font weight

Housekeeping

The edge rate-limit rule's action is a dashboard setting and is deliberately not recorded in a public repository — check it there. Separately, Kalam is still loaded at weight 300 for a handful of elements, costing its own font file.

Why accounts still go last

It is the only item that adds ongoing work rather than removing it: a database to keep alive, auth email deliverability, and an account-deletion path. The commitment outlasts the build. Worth deciding you want that before starting.
