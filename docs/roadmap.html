Progress that survives the browser

Biggest gap

Chapters read, exercises solved, streaks and review schedule all live in localStorage on one device. Clear the browser and it is gone; open the site on a phone and it starts from zero. The storage layer is one seam — every progress-aware component reads through useSyncExternalStore, so a synced implementation touches no components.

Search index size

Measured

Fetched lazily on the first keystroke, so it costs nothing to a reader who never searches — but the interview index is 134 KB gzip and DSA is 115 KB, and those are the two people search most. Trimming HTML out of the indexed text roughly halves it.

Rate limiting that actually holds

Config only

/api/tts has a per-instance limiter, which is a floor rather than a guarantee — serverless spreads traffic across instances. Vercel Firewall is the account-wide version.

Errors nobody sees

Seam exists

Client errors post to /api/client-error and land in the function log: no grouping, no alerting, and the log expires. ErrorReporter.tsx is already the swap point.

Offline reading

Decision first

app/manifest.ts exists; the service worker does not. The fiddly part is that the App Router serves RSC payloads as well as HTML, so caching has to cover both — and the playground needs 18 MB of wasm, which should not be precached by default.

Content pipeline

Half done

The size problem is solved — the four files that had grown past editing are now barrels over per-chapter files. What remains is that chapter bodies are HTML strings with no schema, so a malformed chapter renders oddly instead of failing the build.

The interview book as a product

Blocked

27 rounds and 405 questions is the most obvious thing here to charge for. It needs accounts, then payments, then a gate — and nothing in it starts before accounts do.

9 to 13 days for all five The first three come to about a day and a half together and none depends on another — one sitting closes all three.

Why accounts go last

It is the only item on the list that adds ongoing work rather than removing it: a database to keep alive, auth email deliverability, and an account-deletion path. The build is 5 to 8 days — provider and schema 1–2, the synced storage layer 2, migration and signed-out behaviour 1–2, tests 1 — but the commitment outlasts the build. Worth deciding you want that before starting.
