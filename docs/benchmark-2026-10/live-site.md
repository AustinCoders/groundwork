# Groundwork live-site product audit (https://groundwork.austincoders.com)

Audit date: 2026-10-21. Repo: /Users/akshat/Desktop/groundwork at commit 5a885ab (HEAD = origin/main, working tree clean). No repo file was edited. Raw crawl data sits in `.../scratchpad/live/` (status.tsv, analysis.json, pages/*.html).

Legend: OBSERVED = I fetched or measured it (command or URL given). INFERRED = my conclusion.

---

## Summary verdict

The live site is a technically clean, honest, current product. It matches `main` exactly (same 1,388 URLs, chapter text matches the repo, the newest commit's feature is deployed), all 1,388 sitemap URLs return 200, there are no "notes are not written yet" placeholders inside any written chapter, unwritten topics are labelled "Not written yet / Coming soon" on every page that shows them, the home numbers are generated from data and almost all of them reproduce.

The problems are not breakage. They are (a) a few headline claims that are stretched ("Handwritten", "every idea ... followed by an exercise graded by real tests", "420+ interview questions answered", "Every topic a developer needs"), (b) JS and React chapters that are about a third of the site's own length standard, (c) 69% of indexed URLs are thin 200-word problem pages with no structured data, (d) zero trust metadata on learning pages (no byline, no date, no sources, no report-a-problem), and (e) missing product basics that big learning sites ship (about, contact, changelog, accessibility statement, cross-device progress, offline).

Grade by area: currency A, home-page truthfulness B-, crawl health A-, SEO B-, performance and accessibility basics A-, mobile A-, trust signals C, product basics C+.

## Scope and method

- Fetched /, /sitemap.xml, /robots.txt, then every one of the 1,388 sitemap URLs with curl (8 parallel workers, one run, plus retries). Saved HTML, parsed with Python (title, description, canonical, og, twitter, JSON-LD, headings, landmarks, links, word counts, placeholder strings).
- Measured repo ground truth with `npx tsx --tsconfig tsconfig.json <script>` using `lib/content.ts`, `lib/topicStats.ts`, `lib/interviewContent.ts`, `app/sitemap.ts`. Scripts in the scratchpad (count.ts, c2..c8.ts).
- Sampled 40 pages for a manual content check (table below) on top of the full crawl.
- Mobile: Browser pane at 375x812, measured horizontal overflow, tap-target size and request counts on 8 pages (iframe measurement was blocked by `X-Frame-Options: DENY`, so I navigated).
- Contrast: extracted all 9 theme token sets from the live CSS and computed WCAG ratios.
- Competitors (public pages only, normal fetches, one or two per site): developer.mozilla.org, javascript.info, neetcode.io, www.geeksforgeeks.org. WebFetch summaries come from a small model, so I treat them as medium confidence and say so.

Caveat: this audit's browser pane is shared with other agents (the tab navigated away from my page mid-measurement once). I discarded that reading and used CSS-token contrast instead.

## Hard truths

1. The site calls itself "handwritten" and says "written by hand" while the repo documents an agent pipeline. If a reader finds docs/content-standard.md or the commit history, that line will read as dishonest. The rest of the site is unusually honest about labels, which makes this one stand out more.
2. 25 of 30 topics, 358 of 593 chapter slots, are empty. The shelf is honest about it, but the home page still sells "the whole map" and a Backend roadmap where 7 of 13 steps do not exist. For a visitor who wants Node, Python, SQL or Docker, the site has nothing today.
3. JS and React, the topics most visitors will test first, are the thinnest relative to the site's own standard (median 1,367 and 796 prose words, standard 3,500 to 5,000). DSA and System Design are where the volume is.
4. "955 exercises" includes at least 8 duplicate pairs, and 69% of indexed URLs are 200-word problem pages. As an SEO footprint the site is much smaller than 1,388 pages.
5. 107 of 253 written chapters have no exercise, despite the FAQ line that every idea is followed by one.
6. "420+ interview questions answered" is about 54% full answers, 46% one-line bullets.
7. No page shows an author, date, source or reviewer on JS, React and DSA. The data is already there and simply not rendered.
8. All progress is in the browser's localStorage; clearing site data deletes it, and there is no export or sync. For a product whose pitch includes streaks, spaced review and XP, that is a retention risk.
9. Solo operator: contact is a single mailbox, no about page, no community, no public issue tracker, CI runs on the author's machine (the architecture chapter says "There is no CI service"). Bus factor 1.
10. Company-question data rests on public write-ups and prep lists, labelled correctly, but none of it is first-party candidate data; 71 of 153 are a single write-up.
